# tAIlor

AI-powered wardrobe assistant built with React, Vite, TypeScript, and Tailwind CSS.

## Getting started

```bash
pnpm install   # or npm install
pnpm dev       # or npm run dev — starts Vite and the AI backend
pnpm build     # production build into dist/
pnpm preview   # serve the production build locally
```

Requires Node.js 22 (see `.node-version`).

## AI stylist + wardrobe photo scanner

The app talks to a local Node server (`server/server.mjs`) which proxies to an
OpenAI-compatible model server (local GPU or Google Colab via cloudflared).

| Endpoint | Purpose |
| --- | --- |
| `POST /api/stylist` | Outfit recommendations (text) |
| `POST /api/wardrobe/scan` | Photo → wardrobe JSON (Qwen2.5-VL or mock) |
| `GET /api/wardrobe/scan/health` | Scanner mock/live status |

Copy `.env.example` to `.env`.

### Mock mode (intentional demo path)

With `WARDROBE_SCAN_MOCK=true`, or by selecting a mock sample, Wardrobe →
**Add Item** → **AI Photo Wardrobe Scanner** uses deterministic demo JSON.
Live scan failures now return a descriptive error instead of silently showing
demo data.

### Live Qwen2.5-VL (Colab)

1. Open [`tailorbackend.ipynb`](./tailorbackend.ipynb) in
   [Google Colab](https://colab.research.google.com/) (or upload it).
2. **Runtime → Change runtime type → T4 GPU**.
3. Run the notebook cells in order. They install deps, start `colab_server.py`
   with both the text and vision Qwen models, and print a cloudflared URL.
4. Qwen weights download **anonymously** — no Hugging Face token required.
5. Set local `.env`:

   ```text
   LLM_BASE_URL=https://your-random-name.trycloudflare.com/v1
   LLM_TEXT_MODEL=Qwen/Qwen2.5-3B-Instruct
   LLM_VISION_MODEL=Qwen/Qwen2.5-VL-3B-Instruct
   LLM_QUANTIZE=true
   WARDROBE_SCAN_MOCK=false
   ```

6. Restart with `pnpm dev`. Wardrobe photo uploads call Colab
   `POST /v1/wardrobe/scan`. The text model uses 4-bit NF4 quantization on a
   CUDA runtime, while the vision model stays in float16 to avoid quantizing
   its vision tower. If the tunnel drops, the Node proxy reports the live scan
   failure; use the explicit mock path only for demos.

### Colab server contract

`colab_server.py` exposes:

- `GET /health` → `{ status, models, devices, endpoints }`
- `POST /v1/chat/completions` → OpenAI-compatible text chat (image messages use the vision model)
- `POST /v1/wardrobe/scan` → `{ image: base64, mimeType? }` →

  ```json
  {
    "item": {
      "name": "Teal Gabardine Trench",
      "category": "Outerwear",
      "color": "#007880",
      "colorName": "Deep Teal",
      "material": "Gabardine cotton blend",
      "careInstructions": "Dry clean or gentle cold wash",
      "storageLocation": "Closet · Main Rack",
      "sentimentalValue": "Medium",
      "cost": "$89",
      "confidence": 0.94
    },
    "model": "Qwen/Qwen2.5-VL-3B-Instruct",
    "source": "qwen-vl"
  }
  ```

`category` is one of `Tops | Bottoms | Shoes | Outerwear | Accessories`
(aligned with `WardrobeItem` in `src/types/index.ts`).

### Local GPU (optional)

The same [`colab_server.py`](./colab_server.py) can run directly on a
friend's NVIDIA GPU. It loads both Qwen models and exposes the same API without
Cloudflare.

#### On the GPU computer

1. Install a current NVIDIA driver and confirm CUDA is visible:

   ```bash
   nvidia-smi
   ```

2. Clone this repository and create an isolated Python environment:

   ```bash
   git clone https://github.com/areebasa02/tAIlor.git
   cd tAIlor
   python -m venv .venv
   ```

   Activate it on Windows PowerShell:

   ```powershell
   .\.venv\Scripts\Activate.ps1
   ```

   Or on Linux/macOS:

   ```bash
   source .venv/bin/activate
   ```

3. Install a CUDA-enabled PyTorch build using the command generated by the
   [official PyTorch selector](https://pytorch.org/get-started/locally/), then
   install the server dependencies:

   ```bash
   pip install "transformers>=4.49.0" accelerate fastapi uvicorn pillow
   ```

4. Create a `.env` beside `colab_server.py`:

   ```text
   LLM_TEXT_MODEL=Qwen/Qwen2.5-3B-Instruct
   LLM_VISION_MODEL=Qwen/Qwen2.5-VL-3B-Instruct
   LLM_QUANTIZE=false
   LLM_TEXT_DEVICE=cuda
   ```

   This local path loads both models in full precision on CUDA and does not
   require `bitsandbytes`. The GPU must have enough VRAM for both models. The
   first launch downloads the model weights.

5. Start the server:

   ```bash
   python colab_server.py
   ```

6. Verify it before connecting the app:

   ```bash
   curl http://127.0.0.1:8000/health
   ```

   The response should show both models, `text_quantized: true`,
   `vision_quantized: false`, and CUDA devices.

#### Connect tAIlor to the GPU computer

On the computer running tAIlor, set `LLM_BASE_URL` in `.env` to:

```text
LLM_BASE_URL=http://127.0.0.1:8000/v1
```

when the server is local, or to the GPU computer's private LAN address:

```text
LLM_BASE_URL=http://192.168.x.x:8000/v1
```

If connecting over a LAN, allow inbound TCP port 8000 through the GPU
computer's firewall. Do not expose port 8000 directly to the public internet;
use a private network, Tailscale, or an SSH tunnel instead.

Restart `pnpm dev` after changing `.env`, then verify:

```bash
curl http://127.0.0.1:8787/api/wardrobe/scan/health
```

The proxy should report `mock: false` and the configured vision model.

#### Local GPU memory fallback

If the GPU cannot hold both full-precision models, set `LLM_QUANTIZE=true` and
install `bitsandbytes`; this enables 4-bit NF4 quantization for the text model
only. The vision model remains float16 for compatibility. Alternatively set
`LLM_TEXT_DEVICE=cpu`, but stylist responses will be slower.

#### Equivalent server configuration

```bash
pip install "transformers>=4.49.0" accelerate bitsandbytes fastapi uvicorn pillow
export LLM_TEXT_MODEL=Qwen/Qwen2.5-3B-Instruct
export LLM_VISION_MODEL=Qwen/Qwen2.5-VL-3B-Instruct
export LLM_QUANTIZE=false
export LLM_TEXT_DEVICE=cuda
export WARDROBE_SCAN_MOCK=false
python colab_server.py
```

Set `STYLIST_DEBUG=true` while diagnosing Stylist responses.
`.env` is ignored by git. `pnpm dev` starts the frontend and Node backend
automatically.

## Project structure

- `src/main.tsx` — React entrypoint; imports `src/index.css` and mounts `src/App.tsx`
- `src/App.tsx` — Primary application component
- `src/tabs/` — Top-level screens (Home, Wardrobe, Generator, Try-On, Colors, Laundry, Profile, AI Components)
- `src/components/` — Shared components (login screen, AI UI components)
- `src/context/AppContext.tsx` — Global app state
- `src/types/` — Shared TypeScript types
- `src/index.css` — Global CSS and Tailwind CSS v4 import
- `index.html` — Vite HTML shell
- `vite.config.ts` — Vite config (React, Tailwind CSS v4, `@` → `src` alias)

## Stack

- React 19 + React DOM 19
- Tailwind CSS v4 (`@tailwindcss/vite`)
- Vite 8, TypeScript 5.7, `@vitejs/plugin-react`
- Package manager: **pnpm** (lockfile included; npm also works)

## Deployment

Deployed as a **Render Static Site**.

| Setting | Value |
| --- | --- |
| Build command | `pnpm install && pnpm build` |
| Publish directory | `dist` |

You can also use `npm install && npm run build` if you prefer npm.

A minimal Blueprint is provided in [`render.yaml`](./render.yaml) so Render can pick up the same static-site settings from the repo.

### Hosting local GPU models for teammates via Render + Tailscale Funnel

When Render serves the static site (`dist/`), teammates can run all three AI features (Stylist, Wardrobe Photo Scanner, and SDXL Try-On) against your PC's GPU while your PC is running:

1. Enable **Tailscale Funnel** on your tailnet and confirm `tailscale status` gives your machine's `https://<host>.<tailnet>.ts.net` URL.
2. Set in your local `.env`:
   ```text
   AI_SERVER_HOST=127.0.0.1
   HOST=127.0.0.1
   ALLOWED_ORIGINS=https://your-site.onrender.com
   TAILSCALE_FUNNEL_URL=https://your-host.your-tailnet.ts.net
   RENDER_SITE_URL=https://your-site.onrender.com
   WARDROBE_SCAN_MOCK=false
   ```
3. In your Render Static Site's **Environment** settings, set:
   ```text
   VITE_API_BASE_URL=https://your-host.your-tailnet.ts.net
   ```
4. Launch `tAIlor AI Host` from your Desktop shortcut (or `pnpm host` / `scripts/launch-host.ps1`), which starts `colab_server.py` (`:8000`), `server/server.mjs` (`:8787`), and `tailscale funnel 8787`, and minimizes to the Windows system tray with live logs.

## Cat-VTON virtual try-on

The virtual try-on endpoint uses fal's `fal-ai/image-apps-v2/virtual-try-on`
model. Set these server
environment variables in the git-ignored `.env` file before starting the Node
server:

- `FAL_KEY` — fal API key
- `FAL_MANNEQUIN_IMAGE_URL` — publicly reachable neutral mannequin image URL

Garment photos uploaded through the wardrobe scanner are stored with the
wardrobe record in browser storage and are sent to the server only when a
try-on is requested. The server runs Cat-VTON once for the saved top or
outerwear item, then uses that returned image as the mannequin input for a
second run with the saved bottoms.
